# deal_bot — เครื่องจับดีลจากประวัติราคาจริง

บอทเฝ้าราคาสินค้า เก็บประวัติเอง แล้วแจ้งเตือน Telegram เฉพาะตอนที่
**ลดจริง** ไม่ใช่ตอนที่ร้านติดป้ายว่าลด

**หมวดที่เลือก: ELECTRONICS (ไอที)** — ตั้งค่า default ปรับมาให้หมวดนี้แล้ว

โครงเดียวกับ `alert_bot/` (สแกน → กรอง → แจ้งเตือน → commit ผลกลับ repo)
เปลี่ยนแค่แหล่งข้อมูลจากราคาเหรียญเป็นราคาสินค้า

---

## ทำไมต้องเก็บประวัติเอง

ราคาขีดฆ่าบนหน้าเว็บเชื่อไม่ได้ เล่ห์มาตรฐานคือดันราคาขึ้นก่อนแคมเปญ 1-2 สัปดาห์
แล้วลดกลับมาที่ราคาเดิม พร้อมป้าย -40%

บอทนี้ไม่อ่านป้ายลดราคาเลย ใช้ median ของราคาที่บันทึกเองเป็นฐานอย่างเดียว
และถ้าตรวจพบว่า median 7 วันล่าสุดสูงกว่าช่วงเก่าเกิน 5% จะเปลี่ยนไปใช้
**ฐานราคาเก่า** แทน (คำนวณส่วนลดได้น้อยลง = ผ่านเกณฑ์ยากขึ้น)

ผลพลอยได้: ประวัติราคาที่สะสมคือข้อมูลที่ Google ไม่มีและ AI ตอบไม่ได้
ยิ่งรันนาน ยิ่งมีค่า — และเป็นวัตถุดิบของหน้าเปรียบเทียบราคาในเฟสถัดไป

---

## ปัญหาที่ใหญ่กว่า และเป็นของ electronics โดยเฉพาะ

ของไอทีราคาลดลงเองตามอายุรุ่น SSD/จอ/การ์ดจอ ถูกลงเดือนละ 2-5% เป็นเรื่องปกติ
ถ้าเทียบราคาวันนี้กับ median 90 วันเฉย ๆ มันจะ "ลด 12%" **ตลอดเวลา**
ทั้งที่ไม่มีอะไรเกิดขึ้นเลย บอทจะยิงทุกวันจนไม่มีใครเหลืออยู่ในช่อง

วิธีแก้ 2 ชั้น:

1. **ราคาอ้างอิงใช้หน้าต่างสั้น (21 วัน)** — ราคาเมื่อ 3 เดือนก่อนไม่ใช่ "ราคาปกติ"
   ของวันนี้อีกแล้ว
2. **ลากเส้นแนวโน้มการเสื่อมราคาของสินค้าชิ้นนั้นเอง** (Theil-Sen ใน log space)
   แล้วถามคำถามที่ถูกกว่า — ไม่ใช่ "ถูกกว่าเมื่อก่อนไหม" แต่คือ
   **"ถูกกว่าที่ควรจะเป็นในวันนี้ไหม"** ต้องต่ำกว่าเส้นอย่างน้อย 8% ถึงจะนับ

ทำไมต้อง fit ใน log space: การเสื่อมราคาเป็น "กี่ % ต่อเดือน" ไม่ใช่ "กี่บาทต่อวัน"
ถ้า fit เส้นตรงกับราคาดิบ เส้นจะทิ่มต่ำกว่าราคาจริงตอนปลายช่วง แล้วตัวเลข
drift ที่ได้จะเพี้ยนหลายเท่า (ตอนทดสอบเคยอ่านได้ -74%/เดือน ทั้งที่ของจริง -30%)

ผลพลอยได้ที่ใช้เป็นคอนเทนต์ได้: บอทรู้ว่ารุ่นนี้ปกติถูกลงเดือนละกี่ %
จึงบอกคนอ่านได้ตรง ๆ ว่า *"ถ้าไม่รีบใช้ รออีกเดือนอาจได้ราคาใกล้เคียงกัน"*
เสียยอดคลิกบ้างก็ยอม — ความเชื่อถือคือสิ่งเดียวที่ทำให้ช่องนี้มีค่า

## โครงสร้าง

| ไฟล์ | หน้าที่ |
|---|---|
| `config.py` | เกณฑ์ทั้งหมด + โหลด watchlist (ปรับผ่าน env ได้ทุกค่า) |
| `sources.py` | ดึงราคา — JSON-LD ก่อน แล้วค่อย regex; มี MockSource ไว้ซ้อม |
| `store.py` | SQLite ประวัติราคา + ประวัติการยิง alert |
| `detector.py` | **ตรรกะจับดีล** — pure function ทั้งไฟล์ ทดสอบย้อนหลังได้ |
| `affiliate.py` | สร้าง deeplink + ฝัง sub-id tag สำหรับวัด EPC ทีหลัง |
| `telegram_alert.py` | จัดรูปแบบ + ส่งข้อความ |
| `main.py` | ร้อยทุกอย่างเข้าด้วยกัน + เขียน `status.md` |
| `selftest.py` | เทสต์ detector 13 เคส ไม่ต้องใช้เน็ต |
| `probe.py` | ตรวจว่าดึงราคาจาก URL ได้จริงไหม ก่อนเอาเข้า watchlist |
| `watchlist.json` | รายการสินค้าที่เฝ้า |

## ด่านที่ดีลต้องผ่านครบทุกด่าน

| ด่าน | เกณฑ์ default | เหตุผล |
|---|---|---|
| ข้อมูลพอ | ≥ 10 จุด และ ≥ 14 วัน | ตัดสินจากข้อมูล 3 วันคือการเดา |
| ส่วนลด | ≥ 12% จาก median 21 วันของเราเอง | ตัดส่วนลดหลอกตา |
| **ต่ำกว่าแนวโน้ม** | **≥ 8% ใต้เส้นเสื่อมราคา** | **ด่านที่กัน electronics ไม่ให้ยิงทุกวัน** |
| ต่ำจริง | อยู่ใน 10% ล่างสุดของประวัติ | ราคาที่แกว่งลงเป็นปกติไม่นับ |
| ประหยัดจริง | ≥ 150 บาท | 20% ของ 60 บาทไม่ใช่ข่าว |
| คุ้มค่าคอม | ค่าคอมคาดหวัง ≥ 100 **บาท** | ดูหมายเหตุด้านล่าง |
| ไม่สแปม | ไม่ซ้ำใน 14 วัน เว้นแต่ถูกลงอีก ≥ 5% | ช่องดีลตายเพราะสแปม ไม่ใช่เพราะเงียบ |

### หมายเหตุเรื่องค่าคอม — กติกาเดิมใช้กับ electronics ไม่ได้

ตอนสำรวจตลาดเขียนไว้ว่า "เลือกหมวดที่ค่าคอม ≥ 8%" ซึ่ง**ใช้กับหมวดนี้ไม่ได้เลย**
เพราะสินค้าไอทีทั้งหมวดจ่าย 1-3% ไม่มีข้อยกเว้น

เกณฑ์ที่ถูกต้องกว่าคือวัดเป็น **บาทต่อออเดอร์** ไม่ใช่อัตรา:

| | อัตรา | ราคาต่อชิ้น | ได้จริงต่อออเดอร์ |
|---|---|---|---|
| จอ 27" QHD | 2% | 15,000 | **300 บาท** |
| ครีมบำรุง | 12% | 800 | 96 บาท |

หมวดนี้จึงคุ้มเฉพาะ **ของราคาสูง** — ของต่ำกว่า ~5,000 บาท บอทจะเก็บประวัติราคา
ไว้แต่ไม่ยิงแจ้งเตือน (ค่าคอมไม่ถึง 100 บาท) นั่นคือพฤติกรรมที่ตั้งใจ ไม่ใช่บั๊ก
ถ้าจะขยาย ควรไปทาง โน้ตบุ๊ก / การ์ดจอ / จอใหญ่ ไม่ใช่สาย/เมาส์/แฟลชไดรฟ์

ยิงมากสุด 3 ชิ้นต่อรอบ ที่เหลือพักไว้รอบหน้า

## เริ่มใช้งาน

### 1. ซ้อมก่อน (ไม่ต้องมี key อะไรเลย)

```bash
python -m deal_bot.selftest          # เทสต์ตรรกะจับดีล (13 เคส)
DEAL_DRY_RUN=1 python -m deal_bot.main   # รันทั้ง pipeline ด้วยราคาสังเคราะห์
```

### 2. ใส่สินค้าจริง

แก้ `watchlist.json`

ตอนนี้ใส่ไว้ 8 รายการจาก advice.co.th (จอ 27" 5 ตัว + SSD 1TB 3 ตัว)
เป็น URL จริง แต่**ยังไม่ได้ทดสอบว่าดึงราคาได้** — ดูหัวข้อ probe ด้านล่าง

กติกาเลือกเพิ่ม:
- ค่าคอมต่อออเดอร์ ≥ 100 บาท → ที่อัตรา 2% แปลว่าของต้องเกิน ~5,000 บาท
- เลือกหมวดแคบก่อน คนตามช่องเพราะช่องนั้นรู้ลึกเรื่องเดียว
- เริ่ม 20-40 ชิ้นพอ มากกว่านี้ดูแลลิงก์เสียไม่ไหว

### 2.5 ตรวจว่าดึงราคาได้จริง (ทำก่อนไว้ใจตัวเลขทุกอย่าง)

```bash
python -m deal_bot.probe                      # ตรวจทั้ง watchlist
python -m deal_bot.probe https://... https://...   # ตรวจ URL เดี่ยว
```

หรือกด **Actions → "Deal Bot — Probe URLs" → Run workflow** บน GitHub
(runner เน็ตเปิดเต็ม ต่างจากบางเครื่อง/บาง sandbox ที่โดนบล็อกเว็บไทย)

ผลออกมาที่ `deal_bot/probe_report.md` บอกว่าแต่ละ URL ดึงราคาได้ไหม ด้วยวิธีไหน
(JSON-LD / regex) และถ้าไม่ได้เพราะอะไร

### 3. ตั้ง GitHub Secrets

| Secret | จำเป็นไหม | ใช้ทำอะไร |
|---|---|---|
| `TELEGRAM_TOKEN` | ต้องมี | ส่งข้อความ (ใช้ token เดิมจาก alert_bot ได้) |
| `DEAL_TELEGRAM_CHAT_ID` | ต้องมี | **แชนเนลใหม่แยกจากแชนเนลเทรด** |
| `INVOLVE_API_KEY` | ทีหลังได้ | ไม่มีก็รันได้ แค่ลิงก์ไม่ได้ค่าคอม |
| `INVOLVE_API_SECRET` | ทีหลังได้ | — |

### 4. รอ 14 วัน

บอทจะยังไม่ยิงอะไรจนกว่าจะเก็บราคาครบ 14 วัน — นี่คือพฤติกรรมที่ถูกต้อง
ไม่ใช่บั๊ก ดูความคืบหน้าได้ที่ `deal_bot/status.md` ซึ่ง commit กลับทุกรอบ

## เรื่องที่ต้องรู้ก่อนคาดหวัง

**Involve Asia API ยังไม่ได้ยืนยัน field name** — หน้า docs ต้องล็อกอินถึงเปิดได้
โค้ดใน `affiliate.py` ทำ endpoint/field ให้ override ผ่าน env ได้หมด และ fallback
เป็นลิงก์ตรงเสมอเมื่อเรียกไม่สำเร็จ ก่อนใช้จริงต้องเทียบกับ docs ในบัญชี partner

**ยังไม่มีใครเห็น `HttpSource` เจอเว็บจริง** — sandbox ที่เขียนโค้ดนี้ถูก
network policy บล็อก advice/jib/bnn/mercular/powerbuy ทั้งหมด (403 ที่ proxy)
ตัวแยกราคาผ่านการทดสอบกับ HTML สังเคราะห์แล้ว (JSON-LD ซ้อน `@graph`,
สินค้าหมด, fallback regex) แต่ยังไม่เคยเจอหน้าเว็บ advice ของจริง
**รัน probe workflow ก่อนเป็นอย่างแรก**

**บางเว็บกันบอท** — Shopee/Lazada หน้าสินค้าเป็น JS ล้วนและมีระบบกัน scrape
`HttpSource` จะได้ผลดีกับเว็บร้านค้าปลีกที่ฝัง JSON-LD ไว้ (ซึ่งมีเยอะ
เพราะ Google ต้องการ) ถ้าเจอเว็บที่ดึงไม่ได้ `status.md` จะรายงานให้เห็นทุกรอบ

**โค้ดไม่สร้างคนอ่าน** — บอทนี้แก้ปัญหา "หาดีลจริงเจอ" กับ "ไม่สแปม" ได้
แต่คนเข้าแชนเนลต้องมาจากทางอื่น นั่นคือคอขวดจริงของโปรเจกต์นี้
