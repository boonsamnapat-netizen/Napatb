# deal_bot — เครื่องเลือกว่าสัปดาห์นี้ควรถ่ายคลิปสินค้าตัวไหน

**หมวด:** ELECTRONICS (ไอที) · **advertiser:** Lazada · **ช่องทาง:** Facebook Reels เท่านั้น

บอทเฝ้าราคาสินค้า Lazada เก็บประวัติเอง แล้วออกมาเป็น **คิวถ่ายคลิป**
(`content_queue.md`) พร้อมตัวเลขที่พูดได้ในคลิป — เปิดไฟล์แล้วถ่ายได้เลย

โครงเดียวกับ `alert_bot/` (ดึงข้อมูล → กรอง → สรุปผล → commit กลับ repo)

---

## ทำไมต้องเก็บประวัติราคาเอง

ราคาขีดฆ่าบนหน้าเว็บเชื่อไม่ได้ เล่ห์มาตรฐานคือดันราคาขึ้นก่อนแคมเปญ 1-2 สัปดาห์
แล้วลดกลับมาที่ราคาเดิม พร้อมป้าย -40%

บอทนี้ไม่อ่านป้ายลดราคาเลย ใช้ median ของราคาที่บันทึกเองเป็นฐานอย่างเดียว
และถ้าตรวจพบว่า median 7 วันล่าสุดสูงกว่าช่วงเก่าเกิน 5% จะเปลี่ยนไปใช้
**ฐานราคาเก่า** แทน (คำนวณส่วนลดได้น้อยลง = ผ่านเกณฑ์ยากขึ้น)

ผลที่ได้คือคลิปเราพูดตัวเลขที่ตรวจสอบแล้วได้เต็มปาก ในตลาดที่ทุกคนตะโกนว่าลดราคา
นั่นคือสิ่งเดียวที่เหลือให้แข่ง

## ปัญหาที่ใหญ่กว่า และเป็นของ electronics โดยเฉพาะ

ของไอทีราคาลดลงเองตามอายุรุ่น SSD/จอ/การ์ดจอ ถูกลงเดือนละ 2-5% เป็นเรื่องปกติ
ถ้าเทียบราคาวันนี้กับ median 90 วันเฉย ๆ มันจะ "ลด 12%" **ตลอดเวลา**
ทั้งที่ไม่มีอะไรเกิดขึ้นเลย

วิธีแก้ 2 ชั้น:

1. **ราคาอ้างอิงใช้หน้าต่างสั้น (21 วัน)** — ราคาเมื่อ 3 เดือนก่อนไม่ใช่ "ราคาปกติ"
   ของวันนี้อีกแล้ว
2. **ลากเส้นแนวโน้มการเสื่อมราคาของสินค้าชิ้นนั้นเอง** (Theil-Sen ใน log space)
   แล้วถามคำถามที่ถูกกว่า — ไม่ใช่ "ถูกกว่าเมื่อก่อนไหม" แต่คือ
   **"ถูกกว่าที่ควรจะเป็นในวันนี้ไหม"** ต้องต่ำกว่าเส้นอย่างน้อย 8% ถึงจะนับ

ทำไมต้อง fit ใน log space: การเสื่อมราคาเป็น "กี่ % ต่อเดือน" ไม่ใช่ "กี่บาทต่อวัน"
ถ้า fit เส้นตรงกับราคาดิบ เส้นจะทิ่มต่ำกว่าราคาจริงตอนปลายช่วง แล้วตัวเลข
drift ที่ได้จะเพี้ยนหลายเท่า (ตอนทดสอบเคยอ่านได้ -74%/เดือน ทั้งที่ของจริง -30%)

ผลพลอยได้ที่ใช้เป็นคอนเทนต์: บอทรู้ว่ารุ่นนี้ปกติถูกลงเดือนละกี่ % จึงใส่ประโยค
*"รุ่นนี้ราคาไหลลงเองเดือนละ ~6% ถ้าไม่รีบใช้ รอได้"* ลงในคิวให้พูดในคลิป
เสียยอดคลิกบ้างก็ยอม — ความน่าเชื่อถือคือทั้งหมดที่เรามี

## ทำไมใช้ datafeed ไม่ scrape Lazada

หน้าสินค้า Lazada เป็น JS ล้วนและมีระบบกัน scrape การดึงราคาจากหน้าเว็บจึงทั้ง
เปราะและผิดเจตนาของแพลตฟอร์ม

datafeed เป็นช่องทางที่ advertiser ตั้งใจให้ publisher ใช้ — มีชื่อสินค้า ราคา URL
รูป คำอธิบาย ครบ และให้ทั้ง catalog แทนที่จะต้องไล่ใส่ URL ทีละตัว

| | scrape หน้าเว็บ | datafeed |
|---|---|---|
| จำนวนสินค้า | เท่าที่ใส่มือไหว | ทั้ง catalog |
| โดนบล็อก | เจอแน่ | ไม่เจอ |
| เว็บเปลี่ยน layout | พังทันที | ไม่เกี่ยว |
| ตรงกับที่ได้ค่าคอม | ต้องระวังเอง | ตรงโดยธรรมชาติ |

`HttpSource` ยังอยู่ในโค้ดเผื่อวันหนึ่งอยากเทียบราคาร้านอื่น แต่ไม่ใช่ทางหลักแล้ว

## โครงสร้าง

| ไฟล์ | หน้าที่ |
|---|---|
| `config.py` | เกณฑ์ทั้งหมด + โหลด watchlist/feed config (ปรับผ่าน env ได้) |
| `sources.py` | `FeedSource` (หลัก) / `HttpSource` / `MockSource` |
| `store.py` | SQLite ประวัติราคา + ประวัติการเข้าคิว |
| `detector.py` | **ตรรกะจับดีล** — pure function ทั้งไฟล์ ทดสอบย้อนหลังได้ |
| `affiliate.py` | สร้าง deeplink + ฝัง sub-id tag (มี channel อยู่ในนั้น) |
| `content_queue.py` | **ผลลัพธ์หลัก** — คิวถ่ายคลิป + ประโยคเปิด + ตัวเลขที่พูดได้ |
| `feed_import.py` | สร้าง watchlist จาก datafeed แทนการใส่มือ |
| `main.py` | ร้อยทุกอย่าง + เขียน `content_queue.md` และ `status.md` |
| `selftest.py` | เทสต์ detector 13 เคส ไม่ต้องใช้เน็ต |
| `probe.py` | ตรวจว่าดึงราคาจาก URL ได้ไหม (ใช้กับ `HttpSource` เท่านั้น) |
| `telegram_alert.py` | เก็บไว้เฉย ๆ ปิดอยู่ (`DEAL_TELEGRAM_ENABLED=1` ถ้าจะเปิด) |

## ด่านที่ต้องผ่านครบทุกด่าน

| ด่าน | เกณฑ์ default | เหตุผล |
|---|---|---|
| ข้อมูลพอ | ≥ 10 จุด และ ≥ 14 วัน | ตัดสินจากข้อมูล 3 วันคือการเดา |
| ส่วนลด | ≥ 12% จาก median 21 วันของเราเอง | ตัดส่วนลดหลอกตา |
| **ต่ำกว่าแนวโน้ม** | **≥ 8% ใต้เส้นเสื่อมราคา** | **ด่านที่กัน electronics ไม่ให้เข้าคิวทุกวัน** |
| ต่ำจริง | อยู่ใน 10% ล่างสุดของประวัติ | ราคาที่แกว่งลงเป็นปกติไม่นับ |
| ประหยัดจริง | ≥ 150 บาท | ส่วนลดจิ๊บจ๊อยไม่คุ้มค่าถ่ายคลิป |
| คุ้มค่าคอม | ค่าคอมคาดหวัง ≥ 100 **บาท** | ดูด้านล่าง |
| ไม่ซ้ำ | ไม่ซ้ำใน 14 วัน เว้นแต่ถูกลงอีก ≥ 5% | ถ่ายเรื่องเดิมซ้ำ ๆ คือวิธีเสียคนดู |
| มีของ | ต้องไม่ out of stock ใน feed | ถ่ายคลิปของที่ซื้อไม่ได้ = เสียเที่ยว |

เข้าคิวมากสุด 3 ชิ้นต่อรอบ — เราถ่ายได้สัปดาห์ละไม่กี่ตัวอยู่แล้ว
คิวยาว 20 รายการคือคิวที่ไม่มีใครทำตาม ตัวที่เหลือรอบหน้ากลับมาถ้าราคายังดี

### เรื่องค่าคอม — วัดเป็นบาท ไม่ใช่ %

สินค้าไอทีจ่าย 1-3% ทั้งหมวด ไม่มีข้อยกเว้น เกณฑ์ที่ถูกต้องจึงเป็น**บาทต่อออเดอร์**:

| | อัตรา | ราคาต่อชิ้น | ได้จริงต่อออเดอร์ |
|---|---|---|---|
| จอ 32" 4K | 2% | 14,900 | **298 บาท** |
| ครีมบำรุง | 12% | 800 | 96 บาท |

หมวดนี้จึงคุ้มเฉพาะของราคาสูง — ของต่ำกว่า ~5,000 บาท ไม่ต้องใส่ใน watchlist ด้วยซ้ำ
`feed_import.py` กรองให้ตั้งแต่ต้นทาง (`--min-price 5000`)

## เริ่มใช้งาน

### 1. ซ้อมก่อน (ไม่ต้องมีบัญชีอะไรเลย)

```bash
python -m deal_bot.selftest             # เทสต์ตรรกะจับดีล (13 เคส)
DEAL_DRY_RUN=1 python -m deal_bot.main  # รันทั้ง pipeline ด้วยราคาสังเคราะห์
```

### 2. สมัคร LazAffiliate แล้วขอ datafeed

`lzd.co/LAZAFFREGISTER` — ไม่มีขั้นต่ำผู้ติดตาม

### 3. ต่อ feed เข้าบอท

แก้ `watchlist.json` ส่วน `feed`:

```json
"feed": {
  "enabled": true,
  "path": "deal_bot/feeds/lazada.csv",   // ไฟล์ในเครื่อง หรือ URL ดาวน์โหลด
  "format": "csv",                        // csv | json
  "key_field": "sku",
  "fields": { "name": "...", "url": "...", "price": "...", "availability": "..." }
}
```

`fields` คือ mapping จากชื่อที่โค้ดใช้ → ชื่อคอลัมน์จริงในไฟล์
**เปิดไฟล์ feed ดูหัวตารางก่อนแล้วแก้ให้ตรง** ค่าที่ใส่ไว้เป็นการเดา ยังไม่เคยเห็นไฟล์จริง

### 4. สร้าง watchlist จาก feed

```bash
python -m deal_bot.feed_import --min-price 5000 --limit 40 --dry-run   # ดูก่อน
python -m deal_bot.feed_import --min-price 5000 --limit 40             # เขียนจริง
python -m deal_bot.feed_import --contains "จอ,monitor" --min-price 8000 # กรองด้วยคำ
```

### 5. ตั้ง GitHub Secrets

| Secret | จำเป็นไหม | ใช้ทำอะไร |
|---|---|---|
| `INVOLVE_API_KEY` | ควรมี | สร้าง deeplink; ไม่มีก็รันได้แต่ลิงก์ไม่ได้ค่าคอม |
| `INVOLVE_API_SECRET` | ควรมี | — |

ไม่ต้องใช้ Telegram secret แล้ว

### 6. รอ 14 วัน

บอทจะยังไม่เข้าคิวอะไรจนกว่าจะเก็บราคาครบ 14 วัน — นี่คือพฤติกรรมที่ถูก ไม่ใช่บั๊ก
ดูความคืบหน้าได้ที่ `status.md` ซึ่ง commit กลับทุกรอบ

## ผลลัพธ์ที่ได้

`content_queue.md` ต่อหนึ่งสินค้าในคิว:

- ประโยคเปิดคลิปที่พูดได้เลย (เลือกมุมที่จริงและตรวจสอบได้ ไม่ใช้คำว่า "ถูกที่สุด")
- ตัวเลขที่พูดได้ทุกบรรทัด มาจากราคาที่เราจดเอง
- ค่าคอมคาดหวังต่อออเดอร์
- ลิงก์พร้อม tag สำหรับแปะใน caption
- checkbox ถ่ายแล้ว / โพสต์แล้ว

รูปแบบ tag: `electronics-fbreel-260812-66ea90` — มี channel อยู่ในนั้นตั้งแต่วันแรก
เพราะการเติมทีหลังแปลว่าข้อมูลเก่าใช้ไม่ได้

## เรื่องที่ต้องรู้ก่อนคาดหวัง

**ยังไม่เคยเจอ datafeed จริง** — `FeedSource` ผ่านการทดสอบกับ CSV ที่จงใจตั้งชื่อ
คอลัมน์ไม่ตรง (`item_id`/`title`/`sale_price` + ราคาแบบ `"THB 14,900.00"`) เพื่อพิสูจน์ว่า
mapping และการแปลงตัวเลขทำงาน แต่ไฟล์จริงของ Lazada ยังไม่มีใครเห็น
ต้องเทียบหัวตารางก่อนใช้จริง

**Involve Asia API ยังไม่ได้ยืนยัน field name** — หน้า docs ต้องล็อกอินถึงเปิดได้
`affiliate.py` ทำ endpoint/field ให้ override ผ่าน env ได้หมด และ fallback เป็นลิงก์ตรง
พร้อม tag เสมอเมื่อเรียกไม่สำเร็จ — ลิงก์เสียจะไม่หลุดไปหาคนดู

**Lazada เปลี่ยนระบบ generate ลิงก์** — Involve แจ้งว่าสินค้าบางตัว deeplink ไม่ได้แล้ว
ต้องเช็คเป็นราย SKU ไม่ใช่เหมาว่าได้หมด

**โค้ดไม่ถ่ายคลิปแทนเรา** — บอทแก้ปัญหา "ถ่ายอะไรดี" กับ "พูดตัวเลขอะไร" ได้
แต่ความสม่ำเสมอในการโพสต์คือต้นทุนจริงที่โค้ดช่วยไม่ได้เลย
